# Задание Claude Code: этап 1 — безопасно отделить JavaScript от тяжёлого HTML

Проект: «Дикое поле»; GitHub: stasiya408-dev/pustosh; основная ветка main.
Дата постановки: 23.10.2026.

## Цель
Упростить последующее редактирование игры через GitHub, вынеся ТОЛЬКО исполняемый JavaScript из большого index.html в один или несколько небольших файлов в папке js/. Все изображения, GIF, MP3, data URI, CSS, игровой интерфейс и существующая логика должны остаться работоспособными. Никакого сжатия, конвертации, удаления или выноса медиа в assets/.

## Прежде чем менять
1. Прочитай PROJECT_CONTEXT.md, CLAUDE_START_HERE.md, CLAUDE.md.
2. Проверь git status. Если есть незакоммиченные изменения — не затирай их, сообщи владельцу. Затем получи актуальный main (git pull --ff-only origin main при чистом дереве).
3. Изучи фактический index.html и все места с inline JavaScript: script, inline event handlers, JS в строках, document.write, динамическое создание script, глобальные зависимости, порядок инициализации, переменные, связанные с window, DOMContentLoaded, onload, localStorage, Telegram WebApp.
4. До изменений зафиксируй фактическую версию, число скриптов, размер файла и способ хостинга. Сделай точку отката через коммит/тег или резервную копию.
5. Сначала представь короткий план и риски; при сомнениях запроси подтверждение.

## Безопасная миграция
- Сохрани index.html как входную точку. Сначала выдели самый независимый блок JS в js/*.js, а не все скрипты разом.
- Подключай внешние скрипты относительными путями (например, <script src="./js/game-core.js"></script>), сохраняя ИСХОДНЫЙ порядок выполнения и момент загрузки. Не добавляй defer/async/type=module автоматически: это меняет семантику.
- Не меняй идентификаторы, глобальную область видимости, обработчики, ключи сохранений, структуру DOM, CSS и правила выбора сцен без необходимости.
- Внутренние строки с </script>, data URI, JS-шаблоны и document.write требуют особого внимания; перенос должен быть семантически эквивалентным.
- Оставь медиа встроенными в HTML. Не используй результат v190 и папку assets.
- Не вводи сборщик, зависимости, npm, фреймворк или новую систему публикации на этом этапе.
- Если хостинг не отдаёт js/ или есть CSP/кеширование/особенности Telegram WebView, сначала выясни это и остановись до согласования. Не оставляй сломанную рабочую версию.
- При наличии HTML-атрибутов onclick и подобных оставь совместимые глобальные функции доступными через window.
- Поддержи прежнюю работу игры при открытии по её реальному HTTPS URL. Открытие через file:// может отличаться; отдельно проверь оба способа, если они используются владельцем.

## Что обязательно сохранить
- Старая хата: кот, его анимации, звуки, комнатные предметы и эффекты — только внутри сцены room.
- Ночной лагерь: собственный анимированный фон, без кота и комнатных эффектов; без тестовой скамьи.
- Сад: отдельная сцена.
- Казак общий для сцен; одежда, экипировка, прогресс и сохранения не сбрасываются.
- Остальные механики: боссы, походы, рынок, таверна, инвентарь, таланты, звук, Telegram Mini App и мобильный формат 9:16.

## Проверки
1. Статически проверь отсутствие синтаксических ошибок JS (например, node --check для вынесенных файлов, если Node установлен).
2. Сравни до/после все script-подключения и порядок выполнения; проверь, что ни одна функция не потеряна.
3. Проверь загрузку внешних JS по HTTPS без 404 и ошибок консоли.
4. Пройди главный экран и все ключевые разделы, переключение room → siege → garden → room, кота, звуки, анимации, одежду, сохранение состояния после перезапуска.
5. Проверь в Telegram Mini App на мобильном 9:16, если есть доступ к тестовому окружению. Если доступа нет — явно укажи, что не тестировалось.
6. Сделай миграцию поэтапно; если обнаружены регрессии — откати только свои изменения.

## GitHub и отчёт
- Не редактируй main параллельно с другим агентом. Предпочтительно отдельная ветка + PR для проверки; прямой push в main только с согласия владельца.
- Версию повышай от фактической текущей, не ставь v190/v191 вслепую.
- Обнови CLAUDE.md: список перенесённых функций, файлы, причины, риски и результаты проверок.
- В отчёте дай размеры index.html до/после, перечень новых js/*.js, результаты тестов, что осталось внутри HTML, ссылку на PR/коммит.
- Не заявляй, что вся игра стала легче по общему объёму: на первом этапе меняется только структура и удобство редактирования.

## Критерий готовности
Основной index.html существенно проще редактировать, JS вынесен без потери функциональности, встроенные изображения/GIF/звуки по-прежнему работают, сцены изолированы как прежде, тесты не выявили регрессий. Если безопасно вынести код без переработки зависимостей нельзя — сначала сообщи о блокерах, не ломай игру.
